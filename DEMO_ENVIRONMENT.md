# SAVEAT — демо-окружение

Постоянная тестовая среда: три заведения с владельцами, менеджерами и
сотрудниками, 34 предложения, которые не истекают, и три покупателя.
Всё лежит в **отдельной локальной базе** и не касается production.

## Быстрый старт (Windows)

Нужны Docker Desktop (запущен), `uv` и Node.js.

1. Один раз впиши пароль для демо-аккаунтов в `backend/.env`
   (файл в `.gitignore`, в GitHub не попадает):

   ```text
   DEMO_ACCOUNT_PASSWORD=придумай-пароль
   ```

2. Терминал 1 — база, миграции, демо-данные и backend:

   ```powershell
   .\demo.ps1
   ```

   Если PowerShell не разрешает запуск скриптов:
   `powershell -ExecutionPolicy Bypass -File .\demo.ps1`

3. Терминал 2 — frontend, как обычно:

   ```powershell
   cd frontend
   npm run dev -- -p 3001
   ```

Открой http://localhost:3001. Данные переживают перезапуск backend,
frontend, Docker и компьютера: база хранится в Docker-томе
`saveat-demo-data`.

`.\demo.ps1` запускает backend на демо-базе только для своего процесса.
`backend/.env` при этом не меняется, и обычный запуск
(`uv run uvicorn app.main:app --reload --port 8001`) по-прежнему идёт в
базу из `.env`.

## Команды

| Команда | Что делает |
|---|---|
| `.\demo.ps1` | поднимает базу, применяет миграции, досоздаёт недостающее, запускает backend на :8001 |
| `.\demo.ps1 seed` | только досоздаёт недостающие строки; повторный запуск ничего не дублирует |
| `.\demo.ps1 check` | проверяет связи, остатки, сроки и все картинки (нужен интернет) |
| `.\demo.ps1 reset` | вручную возвращает исходное состояние (см. ниже) |
| `.\demo.ps1 stop` | останавливает базу, данные остаются |

Без PowerShell-скрипта то же самое делается так (из `backend/`):

```bash
docker compose -f ../docker-compose.demo.yml up -d --wait
export DATABASE_URL=postgresql+psycopg://saveat_demo:saveat_demo@127.0.0.1:54330/saveat_demo
export DEMO_OFFERS_AUTO_RENEW=true
uv run alembic upgrade head
uv run python -m scripts.demo_env seed     # seed | check [--images] | renew | reset
uv run uvicorn app.main:app --reload --port 8001
```

Удалить демо-базу полностью: `docker compose -f docker-compose.demo.yml down -v`.

## Заведения и предложения

| Заведение | Точки | Предложений |
|---|---|---|
| Sweet Bakery — торты, пирожные, макаронс | Проспект Достык 91 | 12 |
| Golden Crust — круассаны, багеты, хлеб на закваске | Кабанбай батыра 83; Проспект Абая 44 | 11 |
| Корица — синнабоны, пончики, печенье, пироги | Самал-2, 58 | 11 |

Окна выдачи по времени Алматы:

- **09:00–22:00** («дневные») — заказ можно сразу выдать;
- **18:00–22:00** («вечерние») — до 18:00 покупатель может отменить заказ
  (отмена закрывается с началом выдачи — это реальное правило, его не
  отключали).

В корзине могут быть товары только одной точки, и у них должно быть
общее окно выдачи — это тоже реальная логика checkout.

## Почему предложения не истекают

У предложений есть флаг `offers.is_demo` (миграция `9d4e2b7a1c35`). Его
ставит только `scripts.demo_env`; предложения, созданные заведениями через
приложение, всегда `false` и истекают как раньше.

Когда в backend включён `DEMO_OFFERS_AUTO_RENEW=true` (`demo.ps1`
включает его сам), фоновая задача при старте и затем раз в 5 минут
находит демо-предложения, окно которых закрывается в ближайшие 10 минут
или уже закрылось, и сдвигает его на целое число дней вперёд. Время суток
и длина окна сохраняются, а остатки, статусы и заказы не трогаются.
Поэтому витрина работает и через несколько недель без ручных скриптов.
Код — `backend/app/demo_offers.py`.

## Reset

`.\demo.ps1 reset` запускается только вручную:

- отменяет (не удаляет) открытые заказы на демо-точках;
- возвращает демо-предложениям полный остаток, статус `active` и свежие окна;
- восстанавливает названия, цены, роли и пароли демо-аккаунтов;
- досоздаёт всё, что было удалено руками.

Меняются только строки с фиксированными демо-ID. Другие данные в базе
reset не трогает.

## Как проверить сценарии вручную

**A — бронирование.** Войди как `customer1`, добавь «Синнабоны, 4 шт»
(Корица) в корзину и оформи заказ. Остаток на карточке уменьшится на 1,
заказ появится в «Мои заказы».

**B — сотрудник.** В другом браузере (или инкогнито) войди «Для бизнеса»
как `korica.staff1`. Заказ виден в кабинете Корицы. Подтверди выдачу по
коду из заказа — у покупателя статус станет «Выдан».

**C — два устройства.** `customer1` и `customer2` открывают «Ягодный торт»
(3 шт.). Первый берёт 2, второй после обновления видит 1, и система не
даст ему взять 2. С телефона в той же Wi-Fi сети открой frontend по
IP компьютера. Если backend нужен с телефона напрямую, добавь адрес в
`CORS_ORIGINS` и запусти uvicorn с `--host 0.0.0.0`.

После тестов `.\demo.ps1 reset` вернёт всё как было.

## Защита production

- `scripts.demo_env` отказывается писать в нелокальную базу.
  `--allow-remote-database` — только для отдельной staging/демо-базы,
  никогда для production.
- Если демо-email уже занят чужим аккаунтом, seed ничего не пишет.
- Автотесты (`backend/tests/test_demo_environment.py`) идут в
  одноразовой Docker-базе из `docker-compose.test.yml`, как и остальные.
